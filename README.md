# 大肥鱼桌宠 · PySide6 版

一个跑在 Windows 桌面上的小女仆桌宠，PySide6 从零重写。

别的桌宠项目通常也都有透明窗口、拖拽、点击反馈——那些不是本项目的重点。
**这里真正想解决的是两件别处做不到的事：**

1. **切换动作时不闪空白帧** —— 106 个动作、25 400 帧，切换时画面立刻接上，不会出现"空一下 / 卡一下 / 闪一下"
2. **鱼群** —— 十只不是各玩各的，而是靠 Boids 涌现成一群：会挤、会散、会一起逃

---

## 特色一：切动作不闪空白帧

### 空白帧是怎么来的

逐帧动画桌宠最常见的做法是「一个动作 = 一段序列 / 一个视频 / 一个 GIF」，
切动作时先停掉旧的，再去解码新的。新动作的第一帧要等磁盘读完、解码完才出得来，
这中间的几百毫秒就是屏幕上那段**空白（或者定在上一帧不动）**。

动作越多、切得越勤，这个问题越明显。本项目有 106 个动作，
走路、跑、螃蟹走、待机、各个交互动作之间来回切，按老做法几乎每切一次闪一下。

### 这里的做法

| 机制 | 位置 | 作用 |
|---|---|---|
| **首批就开播** | `src/runtime/loader.py` 的 `FIRST_BATCH = 60` | 解码线程解到第 60 帧就 `first.emit()`，主线程立刻开播，不等剩下 181 帧 |
| **动作帧缓存** | `src/runtime/frame_cache.py` | 最近 3 个动作的帧常驻内存（LRU），命中就**同步换帧**，同一个 tick 内换好，完全没有等待 |
| **主线程零转换** | `loader.py` / `frame_cache.py` | 解码与缩放全在工作线程完成；主线程不再做 241 次 `QPixmap.fromImage + scaled`（那段是 130~180ms，正是"卡一下"的根源） |
| **同动作只解一次** | `window.py` 的 `_request_frames` + `_INFLIGHT` | 十只同时切到同一个动作时共享一次解码，不是各解一份 |
| **背压** | `loader.py` 的 `MAX_CONCURRENT_DECODE = 3` | 同时最多 3 个动作在解码，30 只一起切也不会把内存和 CPU 挤爆 |
| **完整播放保护** | `window.py` 的 `_action_incomplete` | 非交互触发的切换排队等当前动作播完，绝不半路截断——动作不会"碎"、不会闪跳 |

两条路径合起来：

- **缓存命中** → 这一个 tick 就把首帧换上去，零空窗
- **缓存未命中** → 首批 60 帧（2.5 秒内容）就绪即开播，剩下的在后台继续解，
  而 60 帧的播放时间远长于剩余 181 帧的解码时间，所以播到一半时后续帧早就备好了

另外帧按**原始 640×360**保存，不预缩放：倾斜和 Q 弹要对位图做 `rotate/scale`，
预缩放的图再变换就是二次重采样（实测锐度只剩 67.6%，肉眼可见发糊）。
改成原图 + `drawImage(目标矩形, 原图, 源矩形)` 一次复合变换后，锐度 95.6%，CPU 几乎不变。

## 特色二：鱼群

不是"十只各走各的"，而是一个**整体行为的群体**。核心在 `src/shared/flock.py`（Boids，纯逻辑、不依赖 Qt），
由 `window.py` 的 `tick_flock()` 每 150 ms 驱动一次。

规模上实测可稳定跑到**两百只**（内存 817 MB、CPU 1.5 核，见下方「提示」里的实测表）。

**三力合成**（`flock_force`）：

| 力 | 参数 | 效果 |
|---|---|---|
| 分离 | `separationRadius = 300`、`separationWeight = 1.0` | 靠太近就互相推开 |
| 聚合 | `cohesionRadius = 600`、`cohesionWeight = 0.2` | 远处的会被轻轻拉回来，不至于散成一片 |
| 方向对齐 | `alignmentWeight = 0.3` | 多数朝左，落单的也转向左 |

`blend = 0.9`：有合力时 90% 听合力、10% 保留随机；没有合力时 100% 随机——
所以既能成团，又不会机械地挤成一坨。

**越挤越跑**（这是"鱼群"的关键手感）：

- `overlap_ratio` 逐只累加，允许大于 1（多只叠成一摞时飙升）
- 漫游概率：0.25 基线 →`overlap ≥ 0.8` 时拉满 1.0（`roam_chance_for_overlap`）
- 移动档位随拥挤度自动升级：`step`（挪一小步）→ `crab`（螃蟹走）→ `run`（跑）（`pick_roam_tier`）
- 速度上限 +50%（`speed_up_for`）
- 身体真的重叠时，**聚合力强制归零**——否则会被"想聚在一起"的力反向拽住，挤成一堆不动

**屏幕边缘**：贴边 + 拥挤时给一个反斥力（`wall_repel`），把它们从墙角赶开。

**召唤散开**：多开时先全部叠在屏幕正中循环播待机 2 秒（`SPAWN_HOLD_MS`），
时间一到一起四散奔逃——不是依次刷出来的，是一次爆发。

**预输入、不打断**：拥挤度 `ov ≥ 0.8` 时只记一个"该走了"的意图（`_pending_force_roam_at`），
等当前动作播完再执行，绝不半路截断正在播的动画。

鱼群与单体是**两套完全不同的语义**，互不干扰：

- **群体模式**：刻意允许重叠，靠软推力自己散开
- **单体模式**：硬碰撞、不许重叠，撞上就推着走（见下面「其余功能」）

### 提示：开上百只之前，先把主体改小

多开出去的每一只都**继承主体当时的大小**（`window.py:1288` 的注释：创建时就带过去，
不会"先按标准大小闪一下再缩"）。

按「标准」(0.75) 开上百只，身体会把屏幕铺满——鱼群没有移动空间，只剩互相推挤，
成团、追赶、绕墙这些行为就都看不出来了。所以顺序很重要：

1. 右键主体 →「大小 ▸」→ 选「小」(0.45) 或「迷你」(0.3)
2. 再连点「多开十只」，点到想要的只数
3. 事后再改主体大小**不会**同步到已开出去的个体（各自独立），想统一就改好大小重新开

档位：迷你 0.3 / 小 0.45 / 中 0.6 / 标准 0.75 / 大 1.0 / 特大 1.4 / 自适应。

顺便，标准大小下的实测开销（12 核机器，群体模式，含召唤缓冲 2 秒之后的稳态）：

| 只数 | 内存(RSS) | CPU |
|---|---|---|
| 20 | 551 MB | 约 0.6 核 |
| 100 | 665 MB | 约 1.7 核 |
| 200 | 817 MB | 约 1.5 核 |

内存不是按只数线性涨：动作帧是**共享**的（同一动作只解一份、常驻 3 个动作），
从 20 只加到 200 只只多了 266 MB。所以真正的瓶颈是屏幕空间和观感，不是性能。

## 其余功能

这些是桌宠的常见能力，本项目做到同等水平（但不算特色）：

| 功能 | 说明 |
|---|---|
| **光标倾斜摇晃** | 鼠标在附近移动时，角色以脚底为轴左右倾斜（±3.5°、±5px），弹簧收敛；鼠标静止时保持当前倾角不抖 |
| **拖拽 Q 弹** | 拖着走时沿运动方向拉伸，松手弹一下；单击只弹不拉伸 |
| **单体碰撞** | AABB 硬碰撞 + 推箱子求解：撞人者前进、被撞者被顶走、被撞到屏幕边缘则整条链一起停；拖拽和物理飞行中豁免 |
| **漫游开关** | 关掉后移动类动作变成"原地跑步"（动画照播、不位移），并禁止切到群体模式 |
| **摇晃 / 置顶 / 开机自启** | 右键菜单里的开关，点击即时生效 |
| **DSH 联动**（可选） | 装上 `dsh-plugin/` 后，插件把 Harness 的 `session/event` 转发给桌宠，驱动工作状态动画、余额、碎碎念气泡。**不装插件不影响任何本地功能** |

## ★ 这是一个独立程序，不是 DSH 的附属功能

**桌宠本体完全独立运行，不依赖 DeepSeek Harness。** 装好 PySide6 直接 `python main.py`
就能跑，不需要安装 DSH、不需要任何 AI 服务、不需要联网。

DSH 插件（`dsh-plugin/`）只是**可选外挂**：装上之后桌宠能读到 Harness 的工作状态
（干活时切动作、闲时碎碎念、显示余额）。**不装插件，上面的鱼群、倾斜、Q 弹、碰撞一个不少**；
装了插件，DSH 也只是"给桌宠送事件的人"，桌宠进程始终独立于 DSH 存活 ——
DSH 关掉、重开、崩溃，桌宠都照常待在桌面上。

同理，本项目与 DeepSeek 官方无隶属关系，也不属于 Harness 插件市场的一部分。

三条硬边界，代码里都成立：

1. **零 import 依赖**：`src/` 里没有任何一行 import DSH 的东西，桌宠不知道 DSH 是否存在
2. **单向推事件**：DSH 只通过 HTTP `POST /event` 往桌宠推事件，桌宠从不反向调用 Harness；
   推送端断开，桌宠侧只是「最近没有新事件」，照常自己玩
3. **独立进程 + 单实例**：桌宠自带 `GET /state` 探测，DSH 拉起时发现已有实例就只做事件转发代理，
   绝不复制第二只（`main.py` 的 `--mode stdio` 分支）

反过来，DSH 插件也可以随时卸载，卸载后残留的只是一个不被调用的目录。

## 环境要求

- Windows 10 / 11（用到 Win32 API 做置顶与前台唤起）
- Python 3.10+
- PySide6 ≥ 6.5（开发时用 6.12.0）

```bash
pip install PySide6
python main.py
```

就这两步。**不需要安装 DeepSeek Harness，不需要 API key，不联网也能跑。**
想让它跟 DSH 联动，再去装 `dsh-plugin/`（见上文），不装就只是个单纯的桌宠。

## 两种用法

### 方式 A：下载现成的完整包（推荐，不想折腾就选这个）

去 [Releases](https://github.com/g18831889-cpu/dafeiyu-pyside6-pet/releases) 下载
**`DaFeiyuPet-v1.0.1-win64.zip`**（约 779 MB）：

1. 解压，得到一个 `大肥鱼桌宠` 文件夹，放到哪都行
2. 装依赖（只需一次）：`python -m pip install PySide6`
   或者在文件夹里跑 `python -m pip install -r requirements.txt`
3. 双击 **`启动桌宠.bat`**

包里已经带齐 `frames/`（106 个动作 / 25 400 帧）、`config.jsonc`、全部源码、
`dsh-plugin/`、技能外挂和 `使用指导.md` —— **不用 git，不用再去别处补素材，解压完就能跑。**

### 方式 B：clone 源码自己搭

`git clone` 下来只有源码（几 MB），动画素材要另外从 Releases 补。见下面一节。

## 素材说明（重要）

**git 仓库里只有源码，`frames/` 与 `config.jsonc` 不在仓库内。** 原因有二：

1. 帧素材有 834 MB（`frames/`，106 个动作 / 25 400 张 WebP），超过 GitHub 单文件 100 MB 的限制，塞进 git 会让克隆变得极慢；
2. 动画资源有独立的授权条款，见下节。

### 手动补齐素材

从方式 A 的完整包里直接拿 `frames/` 和 `config.jsonc` 放到项目根目录（和 `main.py` 同级）即可。

`config.jsonc` 是动作池、权重、移动分级。如果项目根目录没有它，程序会依次去这些位置找
（后两个只是兼容旧安装路径的兜底，与 DSH 是否安装无关）：

```
./config.jsonc
~/.dsh/profiles/desktop/node_modules/dsh-pet/assets/config.jsonc
../backup-dsh-pet-原版/assets/config.jsonc
```

## 更新记录

### 未发布

- **修：双击大肥鱼唤起 DSH 后画面定格** —— 点右上角 × 后 DSH 只是被隐藏（Electron 的
  `window.hide()`），Chromium 内部认为窗口不可见，合成器就停止提交新帧。以前用
  `ShowWindow(SW_SHOW)` 从外部把它显示出来，只改了 Win32 的可见位，Chromium 毫不知情，
  于是窗口出来了、也能拖，但画面永远停在最后一帧（任务其实还在跑）。
  现在改成**重新启动一次 DSH.exe**，让 DSH 主进程自己走单实例回调 `window.show()` ——
  和点托盘图标、双击桌面快捷方式同一条代码路径。只在"被隐藏"时这样做，最小化和已可见不受影响。

### v1.0.1（2026-10-30）

两个都是"用久了才暴露"的问题：

- **修：开摇晃后画面明显变糊** —— 之前倾斜帧走 Qt 的 `drawImage`，它只有 2×2 双线性采样，
  3.5° 旋转后高频只剩 71%；1:1 显示（「大」档）时更糟，还叠加了一次"把原图放大再缩回"的无用插值，
  只剩 61%。现在改成按角度档用 **BICUBIC 预渲染 + 缓存**，高频回到 **96.6%**，
  和"不摇晃"肉眼无差。生成的图每帧只是整数 1:1 贴图，零重采样。
- **修：多开偶尔整个进程消失** —— 崩溃日志里是 `0xC0000005`，前面紧跟一串
  `QObject::~QObject: Timers cannot be stopped from another thread`。根因是 QTimer 与窗口互相持有
  （`timer.connect(self.xxx)` 形成循环引用），只能等 GC 回收，GC 一旦落在解码线程里，
  QObject 就在非主线程析构。另外解码队列 `_INFLIGHT` 还强引用着已关闭的窗口。
  现在关闭时会**在主线程当场** `stop → disconnect → 析构 timer`，并把该窗口从所有解码队列里摘掉。

完整包里已带上这两处修复。

首个版本：透明窗口逐帧动画、鱼群、光标倾斜摇晃、拖拽 Q 弹、单体模式碰撞、右键菜单开关。

## 已知限制

- 只在 Windows 上验证过
- 倾斜与 Q 弹依赖 `paintEvent` 里的复合变换，群体模式下只有主体会晃（子体保持静止，省 CPU）
- clone 仓库只拿到源码，素材要另外从 Releases 的完整包里取，见上文「素材说明」
- DSH 联动只对 DeepSeek Harness 生效；换成别的编辑器/IDE，桌宠会退化成纯桌宠（这是设计如此，不是缺陷）
- 摇晃时的高清预渲染需要 `Pillow`（可选依赖）。没装会自动退回 Qt 内置算法，功能不受影响，只是摇晃时略软
